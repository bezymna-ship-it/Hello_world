## C. Ranking for our need (procedural, animatable, quad-only, Python-built)
1. **Ring-stack with support loops in the kernel + G2 outlines (`CC`) + inverse-limit ring fitting.** Only route that gives quad-only, parametric, Apple-grade continuity.
2. **SDS Weight tag via Python** for tight seams / <=0.3 mm edges / knurl ridges without extra loops. Keep the C4D SDS object (Redshift tessellation docs do not mention creases). Not for large radii.
3. **Redshift Round Corners** for micro-chamfer (0.03-0.15 mm [assumption, doc unit mm]) on every edge, incl. final-geometry parts. Normals only: silhouette/shadow unchanged; extra rays = noise on gloss/refraction; default Num samples 6; large radius (0.1 in a cm example) looks excessive. "Consider Same Object Only" off blends bevels between touching objects (a render-time fillet between parts).
4. **Bevel deformer / Boole bevel on non-SDS parts** (screws, vents, hardware): non-destructive, but n-gon/tri corners and circular G1 profile (user profile spline 1205/1206 can encode G2). Never under SDS. Boole cuts: n-gons, use SEL_CUT_EDGES to feed Obevel.
5. Houdini route (PolyBevel+crease -> Alembic with "Creases and Corners", `ALEMBIC_USE_SDSWEIGHTS` exists): unverified, cross-app overhead. Reference only: pure-Python Catmull-Clark `github.com/dbt-ethz/mola`.

## D. Recipes (all tested closed, bnd 0, nonmanifold 0)
**D1 Squircle slab, true G2.** Figma/Apple corner (phamfoo/figma-squircle draw.ts: p=(1+s)R, arc=sin(45(1-s) deg)*R*sqrt2, c,d,b=(p-arc-c-d)/3,a=2b) is G2 with the flat side but has a curvature STEP at Bezier->arc: kappa*R = 1.47 -> 1.0 at s=0.6 (1.39 at s=0.8). Use **clothoid-arc-clothoid** instead (`lnk_cc.CC(cx,cz,ax,az,R,q=0.6,d=0)`, drop-in for RR: attrs ax,az,r(=p), `offset(d)` true parallel curve, `moved`, `map_norm(u,v,lu,lv)`):
```
Ls=q*pi/2*R; La=(1-q)*pi/2*R; Ltot=2*Ls+La      # k ramps 0->1/R over Ls, holds La, ramps down
for i in range(n): k=ramp/hold/ramp(s_mid); th_mid=th-.5*k*ds; x+=cos(th_mid)*ds; z+=sin(th_mid)*ds; th-=k*ds
p=x   # extent along each side, end=(p,-p); p/R: q=0 1.000, .3 1.244, .6 1.5045, .8 1.685, 1.0 1.870
```
`map_norm` = RR's, but corner nodes take fraction f of HALF corner arc length, local=(x-p,z)+d*(-sin th,cos th), other side swaps x/z; straight part ends at ax0-p. Use `slab(CC(...),y0,y1,e=0.3)` unchanged (leg=r/2, 2 segments per half corner = 4/90 deg). Ctor raises if p>min(ax,az). Measured on the 4-seg ring after 5 subdivision levels (R=6): max |dk/ds|*R^2 = 2.60 circular vs 1.06 (q=.6) vs 0.81 (q=1); peak-curvature radius after SDS 5.19 mm (RR) vs 5.62 (CC): pre-scale R by 1.16 / 1.07 to hit a target.
**D2 Edge rings that survive SDS.** In a regular strip the CC section = cubic B-spline, vertex limit (1,4,1)/6, so fit rings to a target profile (`lnk_edge.fit_stack`): `ext=[2C0-C1]+C+[2Cn-Cn-1]; S=(ext[i-1]+4ext[i]+ext[i+1])/6; C[i]+=T[i]-S[i]` (interior only, 12 iters). Target for fillet R, m=2: T=[(-R-tail,0),(-R+R sin f,-R+R cos f) f=0,45,90,(0,-R-tail)]. Result (R=1, tail 2R): rings (t,h) = (-0.678,+0.072),(-0.288,-0.288),(+0.072,-0.678) -> `profile_solid` ring = `outl.offset(t)` at `y_top+h`. Error 0.9% R vs 3.1% for classic one-loop-each-side at same ring count (3.4x better). m=3 worse (3.9%), m=4/6 ~2%; **next ring beyond the tangent must be <=2R** (tail 4R: 4.8%, 8R: unstable, control points overshoot). G2 targets (quintic corner) fit to 0.4-0.6% of p at m=4-6. Chamfer c: split in 3 equal parts, same fit.
**D3 Crease helper (HNWeightTag), for <=0.3 mm edges / ridges:**
```
tag=o.GetTag(c4d.Tsds) or o.MakeTag(c4d.Tsds); tag.InitFromObject()
em={}   # edge -> (poly,k)
for i in range(o.GetPolygonCount()):
  p=o.GetPolygon(i); v=(p.a,p.b,p.c,p.d)
  for k in range(4): em.setdefault(frozenset((v[k],v[(k+1)%4])),(i,k))
tag.SetPolyEdgeWeight(*em[frozenset((a,b))], w)   # w 0..1
```
